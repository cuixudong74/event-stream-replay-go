# event-stream-replay-go

面向事件流的重放与重处理能力。事件持续写入本地追加存储（`Store`），下游
（`Sink`）依据事件维护各自的派生结果。当处理逻辑调整或下游结果出现偏差时，
可以选取历史区间重新处理（`Replayer`），并把新结果投递回下游，同时不影响正在
进行的实时处理（`LiveProcessor`）。

## 架构

```
                ┌──────────────┐
  events ──────▶│ Store (追加)  │◀────────────┐
                └──────────────┘             │
                   │          │              │
            LiveProcessor   Replayer   CheckpointStore
             (实时追尾)      (区间重放)   (原子持久化进度)
                   │          │              │
                   └────┬─────┘              │
                        ▼                    │
                  Sink (幂等下游) ────────────┘
```

`Manager` 协调多个下游：每个下游拥有独立的实时进度与独立的重放任务，
单个下游变慢不会阻塞其他下游，也不会拖慢实时链路。

## 重放语义

### 1. 区间边界精确

`ReplayConfig{From, To}` 为**闭区间**，两个端点都精确生效：重放覆盖且仅覆盖
`[From, To]` 内的全部事件，每个事件恰好投递一次，不多算也不漏算。
区间端点超出已提交位置时重放拒绝启动。

### 2. 重放与实时并发

`LiveProcessor` 与 `Replayer` 相互独立：重放期间新到达的实时事件由实时通道
按序投递并提交，不会丢失或被跳过。两条通道对同一事件的重叠投递由幂等下游
去重，因此两条通道推进结束后，下游状态与对完整历史做一次全量重放的结果一致
（投影采用可交换的合并方式，与投递顺序无关）。

### 3. 幂等投递与可区分原因

`Sink.Apply` 幂等：同一事件 ID 只应用一次。重复投递返回可区分的原因：

| Reason                | 含义                                       |
|-----------------------|--------------------------------------------|
| `applied`             | 首次应用                                   |
| `duplicate-retry`     | 同一通道内的重复投递（重试/恢复重叠）      |
| `duplicate-replay`    | 跨通道重复（重放与实时互相覆盖）           |

重复投递不会再次累计到下游结果中。

### 4. 中断与恢复

每应用 `CommitEvery` 个事件提交一次检查点。检查点通过「临时文件 + fsync +
rename」原子落盘，进程崩溃不会留下部分写入。检查点中实时已提交位置
（`LiveCommitted`）与重放任务状态（`Replay`）分开记录，重启后始终可区分。
恢复时从重放中断前最近一次已提交的位置（`Replay.Next`）继续，已提交的事件
不会重复应用，未提交的事件不会被跳过；崩溃导致的批次内重投由幂等下游吸收。

### 5. 多下游独立进度

每个下游有独立的实时 goroutine、独立的重放任务和独立的检查点文件。
`Manager.Progress(name)` 可随时查询某下游的实时已提交位置与重放状态
（`running` / `done` / `canceled`）。

### 6. 速率、并发、取消与超时

- `RatePerSec`：按事件限速（令牌间隔），防止重放压垮下游或拖慢实时链路。
- `Concurrency`：单个提交批次内的并行投递度；检查点只在整批完成后推进，
  保证已提交前缀连续、无空洞。
- 取消/超时通过 `context` 传递。被取消的重放把状态落盘为 `canceled` 并记录
  明确的 `Next` 位置，下游不会停在部分提交的中间状态；之后用相同区间重新
  运行即可从该位置继续。

### 7. 可复现性

`MemorySink` 的投影由固定种子、事件 ID 与负载确定性导出，合并方式与投递
顺序、重复投递无关。固定输入与固定随机种子下，同一区间的重放结果逐条可复现，
可复现同样的判定结论（见 `TestReplayReproducible`）。

## 配置项（ReplayConfig）

| 字段          | 默认   | 说明                                   |
|---------------|--------|----------------------------------------|
| `From`, `To`  | 必填   | 重放闭区间端点（offset 从 1 开始）     |
| `RatePerSec`  | 不限   | 每秒最多投递的事件数                   |
| `Concurrency` | 1      | 批次内并行投递数                       |
| `CommitEvery` | 16     | 每多少个事件提交一次检查点             |
